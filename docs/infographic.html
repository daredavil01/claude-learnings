claude-learnings

Every rule in it was paid for once. Sixteen were paid for twice.

A skill built from what nineteen repositories recorded about building them: Astro and Cloudflare sites, Supabase and D1 back ends, data stories, interactive pieces and video. It brings the fix from one repo into the next session in any other.

What the ledger showed

The same lessons were learned over and over

Fixes stayed where they were found

Each fix sat in one repo's learnings file, where the next project never looked. The npm 11 lockfile broke Cloudflare's npm 10 build three times in two repos.

Lessons carried forward did not recur

45-days imported its sister project's lessons on day one. Its log has no entry for either problem.

Nine repos had no learnings file

Their lessons lived in a 63 KB CLAUDE.md, decision records, audits and status logs, where nothing marked which were learned the hard way.

Nothing covered the shell

Shell traps, design handoffs, data stories, video and the lessons loop itself had no shared home until now.

How a session uses it

Start, work, check, record

Session start

Read before writing

The repo's CLAUDE.md and learnings file, then git status for another session's files. Check what the repository contains before trusting a document that describes it.

While working

Load the matching pack

Touching the lockfile loads dependencies. Deploying to Pages loads Cloudflare. A stack the repo does not use contributes no rules.

Before calling it done

Run the checklist

Deploy runtime, a failing guard seen once, 375 px in both themes, derived numbers, the reader's time zone, an untouched lockfile.

Session end

Ask what surprised you

Write an entry when surprised, corrected or slowed down, not on a schedule. Scheduled entries are the thin ones.
