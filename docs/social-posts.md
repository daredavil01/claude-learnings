## LinkedIn (long form)

I read through 19 of my own repositories and found I'd fixed the same bugs again and again.

Over the past months I've built NGO sites, a clinic booking system, data stories, scrollytelling pieces and a video studio, mostly with Claude Code. Ten of those repos had a learnings file, and together they held about 360 recorded lessons.

When I put them side by side, the pattern was hard to miss:

→ An npm 11 lockfile broke Cloudflare's npm 10 build three times, in two repos.
→ Overflow that only showed at phone width shipped seven times.
→ `pkill -f vite` killed its own shell in two different projects.
→ A UTC date put readers in India on the wrong day for five and a half hours, twice.

Each fix sat in one repo's notes, and the next project never looked there.

So I turned the whole ledger into a Claude Code skill: **claude-learnings**.

What it does:
• Brings 10 core rules into every session ("a check that has never failed has not been tested")
• Loads 16 rule packs (Cloudflare, Supabase, D1, Astro, Indic languages, design handoffs, AI features and more) only when the repo needs them
• Runs a "before you call it done" checklist
• Keeps a lessons loop going: one entry format across repos, a promotion path from repo → CLAUDE.md → skill, and a script that harvests new lessons

The most useful finding: lessons I carried into a new project on day one never came back. The ones I didn't, did.
